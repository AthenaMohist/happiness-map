## 三方一致项（共识）

1. **方案 C（独立通知 cron）胜出**：三方一致否决 A（deliver 语义不符 + 噪音）和 B（autopilot 膨胀 + set -euo pipefail 风险）
2. **通知 cron 读 pipeline_state.db（结构化），绝不 grep autopilot.log（非结构化文本）**
3. **autopilot.sh（704 行）不允许再膨胀**——新功能必须独立脚本挂载（dedup_check/stuck_check 模式）
4. **产品红线认同**：汇报第一优先级是"不骚扰"，宁漏推里程碑，不可错推例行状态
5. **去抖/聚合/分级三件套**是通知 cron 的必备机制

## 关键分歧点（需 Frank 裁定）

### 分歧 1：Gap 4 健康度报告的形态

- **Product**：独立 P1 功能（每 30 轮=1h 输出摘要到日志+飞书）
- **Engineer**：依赖 Gap 1，必须串行（无通知通道做了也没人看）
- **Architect**：不独立建 cron，作为 Gap 1 通知 cron 的一个推送类型（两个 cron 各读 pipeline_state.db + 发飞书 = 不必要的架构重复）

**倾向**：Architect 方案更优——同一 cron 里做例外检测（实时）+ 每 30 tick 健康摘要（批量），复用去抖逻辑。成本低于两个独立 cron。

### 分歧 2：Gap 2 建卡通道是否伪需求

- **Product/Architect**：技术已通（autopilot L76-102 自动注册手动卡），真缺口 = 文档化 + 内容注入
- **Engineer**：直接质疑 Gap 2 存在性——discover_new_tasks 已覆盖 OC 走 `hermes kanban create` 的路径，唯一真 gap 是内容注入（Gap 5）

**倾向**：三方实际收敛——Gap 2 不需要新开发，只需要：(a) 文档化手动建卡流程；(b) discover 注册时补 claim/wiki/超轮次注入（~10 行）。

### 分歧 3：Gap 3 workspace_kind 合规扫描的优先级

- **Product/Architect**：P2 backlog（团队规模小，风险暴露面有限）
- **Engineer**：P1（main 分支直改是代码安全红线，独立脚本 ~60 行零风险）

**倾向**：成本极低（~60 行，复刻 dedup_check 模式），建议按 Engineer 提到 P1 或至少作为 Gap 1/2 的顺带项。

## Architect 补充的 4 个实现约束（值得采纳）

1. **通知 cron 自带 notify_state.db**（不污染 pipeline_state.db 单一写入者契约——checkpoint.py 明确"只有 autopilot 写入"）
2. **信号源：pipeline_state.db 状态迁移为主 + kanban comment [AUTOPILOT:] 前缀为辅**，不 grep log
3. **feishu 配置外置** config/notify.json（credentials 不进代码）
4. **fail-open**：通知 cron 挂了不影响 autopilot（两个独立 cron 进程）

## Engineer 的 3 个架构风险提醒

1. **cron 间竞态**：通知 cron 与 autopilot 不同步 → pipeline_events 表 notified_at + `UPDATE WHERE notified_at IS NULL` 原子标记
2. **feishu API 限流**：例外事件密集（连续 retry）可能触发限流 → 内置速率限制（同一 task 每小时最多 5 条例外）
3. **notify_state.db 清理**：已完成 task 的事件记录定期清理（建议 7 天滑动窗口）

## 通知 cron 推荐架构（Architect 落地设计，Engineer 成本确认）

```
scripts/notify_cron.sh  (no_agent=True, deliver=local, 每 2min)
  ├─ 读 pipeline_state.db → 快照对比 notify_state.db → 检测状态迁移
  ├─ 读 kanban.db comments → 过滤 [AUTOPILOT:] 前缀 → 补充例外语义
  ├─ 分级：例外实时推 / 里程碑聚合推 / 每30tick健康摘要
  ├─ 去抖：notify_state.db event_hash 冷却窗口
  └─ 推送：curl feishu webhook（config/notify.json 配置）
```

**成本估算**：~140 行（pipeline_events 表 + notify_cron.sh），autopilot.sh 零改动。
